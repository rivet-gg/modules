Every guest process is an entry in the VM's kernel process table, never a host
process. Process operations live under `vm.process`.

- `process.exec(command)` runs a command line through the shell and waits for it
  to finish.
- `process.execFile(file, args)` runs an executable with an argument array. No
  shell parses the arguments.
- `process.spawn(command, args)` starts a long-running process and returns its
  `pid` immediately.

Process arguments are passed as individual argv entries. An empty string is a
valid argument; it is not dropped or treated as an omitted argument. Empty
commands or working directories are invalid input.

## Manage running processes

A spawned process supports:

- `process.writeStdin(pid, data)` and `process.closeStdin(pid)`;
- `process.signal(pid, signal)` and `process.kill(pid)`;
- `process.resizePty(pid, { cols, rows })` for a process started with `pty`;
- `process.wait(pid)`, which resolves with the process's exit;
- `process.get(pid)` and `process.list()`, which report `startedAtMs` as a Unix
  timestamp in milliseconds.

`process.tree()` includes guest child processes as well as processes launched
through `vm.process`, so it can show more than you started. Use the returned
`pid` rather than reconstructing one from a node.

A process wait returns an exit only after agentOS observes a guest exit. A
rejected launch or lost exit observation rejects the wait instead of inventing
an exit code. An observation failure does not prove the guest has stopped;
inspect the VM or recreate it before assuming it is safe to retry work.

## Output events and replay

Subscribe to live output with `vm.onProcessOutput(pid, handler)` and to exit
with `vm.onProcessExit(pid, handler)`. Both return an unsubscribe function.

Pass `output: { retainEvents: true }` to `spawn` to retain the process's output
in the sidecar. `process.readOutput(pid, { after, maxEvents, maxBytes })` then
pages through retained output with a sequence cursor, even after the process
has exited or a live event was missed. Retained output callbacks include
`sequence` and `timestampMs` metadata for correlating live output with replay.

A replay page reports `nextCursor`, `hasMore`, and `truncated`, plus `exitCode`
once the sidecar has confirmed the exit. Retention is bounded; see
[Resource Limits](/agentos/docs/resource-limits) for the defaults.

## Interactive shells

`vm.terminal.open(options)` allocates a kernel PTY, starts a shell attached to
it, and returns a `shellId`. Use `terminal.write`, `terminal.resize`,
`terminal.wait`, and `terminal.close` to drive it, and `vm.onShellData`,
`vm.onShellStderr`, and `vm.onShellExit` for its live output and exit.
