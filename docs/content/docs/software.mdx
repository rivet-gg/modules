agentOS software ships as immutable `.aospkg` packages containing real compiled
tools. Installed packages are projected read-only under
`/opt/agentos/pkgs/<name>/<version>`, and their commands are linked under
`/opt/agentos/bin`. Every VM includes a default bundle with `sh`, coreutils, and
the standard CLI tools programs rely on.

Browse the available packages in the [registry](/agentos/docs/registry).

## Registry packages

Registry packages are published with each release under
`https://releases.rivet.dev/agent-os/<version>/software/`, or `latest` for the
newest release. Its `manifest.json` lists each package's name, digest, size,
and path relative to the manifest:

```json
{
  "schemaVersion": 1,
  "artifacts": [
    {
      "name": "git",
      "digest": "sha256:<64 lowercase hex>",
      "size": 17961114,
      "path": "packages/git/<64 lowercase hex>.aospkg"
    }
  ]
}
```

Resolve `path` against the manifest URL to get the package URL, and pass
`digest` along so the bytes are verified before they are installed. Registry
software is distributed only as `.aospkg` files from this location, not as npm
packages. See [Publishing Software](/agentos/docs/custom-software/publishing).

## Default software

Every VM installs a default bundle first: `coreutils` (which provides `sh`),
`sed`, `grep`, `gawk`, `findutils`, `diffutils`, `tar`, and `gzip`. The bundle
ships with the library and the hosted runtime, so it needs no download. Pass
`defaultSoftware: false` to `AgentOs.create()`, or set `"defaultSoftware": false`
in a hosted VM's `config`, for a bare VM that has only the software you list.

## Install while running

Install a package into a running VM from an HTTPS URL, with an optional exact
`sha256:<64 lowercase hex>` digest. The library also accepts a trusted local
path.

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });
const vm = client.agentOS.getOrCreate(["my-vm"]);

// Registry software is published as digest-addressed .aospkg files next to a
// manifest. Use a release version, or `latest`.
const base = "https://releases.rivet.dev/agent-os/latest/software/";
const { artifacts } = await (await fetch(`${base}manifest.json`)).json();
const ripgrep = artifacts.find((artifact: { name: string }) => artifact.name === "ripgrep");

const installed = await vm.v1.software.install({
	source: { url: new URL(ripgrep.path, base).href, digest: ripgrep.digest },
});
if (installed.config.state === "restart_required") {
	await vm.v1.vm.restart({});
}

for (const software of await vm.v1.software.list({})) {
	console.log(software.packageId, software.commands);
}

const { packageId } = installed.source;
if (packageId) await vm.v1.software.uninstall({ packageId });
```

</CodeGroup>

On hosted VMs, software is part of the VM's durable configuration, so install
and uninstall use the same revision checks as `v1.config.patch`. A change
applies live when the VM is ready and its desired configuration is fully
applied; otherwise it reports `restart_required`, and `v1.vm.restart` applies
it. Both mutations return `{ source, software, config }`. `v1.software.list`
reads the live installed set, and the desired package sources live in
`v1.config.get`.

In the library, `software.install(source)` returns the installed package's
`packageId`, `digest`, `sizeBytes`, `packageName`, `version`, and `commands`.
`software.installed()` lists packages installed through `software.install`, and
`software.list()` reports every package that provides commands in the VM. Only
one software or mount mutation runs at a time per VM; a concurrent call fails
with `invalid_state` instead of queueing.

## Install when the VM is created

<CodeGroup>

```ts Hosted @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({ endpoint: "https://api.rivet.dev" });

// Look up the package in a release manifest. Use a release version, or `latest`.
const base = "https://releases.rivet.dev/agent-os/latest/software/";
const { artifacts } = await (await fetch(`${base}manifest.json`)).json();
const git = artifacts.find((artifact: { name: string }) => artifact.name === "git");

const vm = client.agentOS.getOrCreate(["my-vm"], {
	createWithInput: {
		config: {
			software: [{ url: new URL(git.path, base).href, digest: git.digest }],
		},
	},
});
```

<CodeSnippet file="examples/embedded/software.ts" title="Library" />

</CodeGroup>

Hosted VMs take `{ url, digest }` sources in their `software` config, and
download and verify them when the VM starts. The library's `software` option
takes `{ packagePath }` references to trusted `.aospkg` files on the host, so
the library example downloads the registry package once, verifies its digest,
and passes the cached file. To install from a URL without a local file, create
the VM and call [`software.install`](#install-while-running) before you run
anything that needs the package.

## Custom and local packages

A package you build yourself, or any other `.aospkg` file, installs the same way
as a registry package. See
[Software Package Definition](/agentos/docs/custom-software/definition) and
[Building Software](/agentos/docs/custom-software/building-wasm) for how to
build one.

The library reads trusted local paths, both in `software` at creation and with
`software.install({ type: "path", path })` while running. Hosted VMs cannot read
files from your machine, so upload the `.aospkg` to an HTTPS location you
control and pass its URL and `sha256:` digest, at creation or with
`v1.software.install`.

## Verification and caching

Each URL source is downloaded under strict size, time, and redirect limits,
verified against the expected digest when one is given, and validated before
it is projected. The verified content digest is the package identity.

Packages are cached by content digest, so VMs that share a worker or sidecar
reuse one verified copy, and repeat installs of the same bytes skip the
download. Hosted workers also warm popular packages at startup; see
[Software Installation and Preloading](/agentos/docs/architecture/software-cache).

## Embedded API

The embedding process is trusted, so `software.install` accepts local package
paths as well as URLs. Read more in the
[embedded API quickstart](/agentos/docs/quickstart-embedded).
