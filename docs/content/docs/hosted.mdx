agentOS ships as a prebuilt `agentOS` Rivet Actor. Each actor is one durable
VM: create it by key, then control its files, processes, terminals, software,
networking, schedules, and language runtimes from the RivetKit client or plain
HTTP. Configuration persists with the VM, output survives reconnects, and every
VM can expose expiring previews.

Applications do not write an actor definition or lifecycle hooks. Product
state and hooks belong in your own actors, which call the `agentOS` actor as a
separate service.

<Note>
The hosted contract is in alpha (`agentos-sdk.dev/v1alpha1`). The actor and the
`@rivet-dev/agentos` client ship in lockstep. See
[Hosted VM API](/agentos/docs/actor-api#contract-compatibility).
</Note>

## Install

```bash
npm install @rivet-dev/agentos
```

## Create a VM by ID

The TypeScript client is generated from the same contract as the HTTP API, so
every action, event, and result is typed. `createAgentOsClient` is a normal
RivetKit client with that contract applied.

<CodeGroup>

```ts TypeScript @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

const client = createAgentOsClient({
	endpoint: "https://api.rivet.dev",
	namespace: process.env.RIVET_NAMESPACE,
	token: process.env.RIVET_TOKEN,
});

const vm = client.agentOS.getOrCreate(["my-vm"], {
	createWithInput: { config: { environment: { CI: "true" } } },
});
const vmId = await vm.resolve();
```

```bash cURL
curl -X PUT "https://api.rivet.dev/actors?namespace=$RIVET_NAMESPACE" \
  -H "Authorization: Bearer $RIVET_TOKEN" \
  --json '{
    "name": "agentOS",
    "key": "my-vm",
    "runner_name_selector": "services",
    "crash_policy": "sleep"
  }'
# → { "actor": { "actor_id": "…" }, "created": true }
```

</CodeGroup>

Creation input is used only when the actor is first created. Calling
`getOrCreate` with different input for an existing key does not reconfigure
it; use the [config actions](/agentos/docs/actor-api#configuration) instead.

Every public action lives under `v1`. In TypeScript that is `vm.v1.<group>.<action>(input)`.
Over HTTP, call `POST /gateway/{actor_id}/action/v1.<group>.<action>` with the
input as the single element of `args`. See
[Call Action](/docs/api/gateway/call-action).

## Public access with JWTs

Keep your admin token on the backend and issue a JWT scoped to one VM.
Browsers and other untrusted clients can then call that VM directly, and
nothing else. See [JWTs](/docs/jwt).

<CodeGroup>

```ts TypeScript @nocheck
import { createAgentOsClient } from "@rivet-dev/agentos";

// Backend: issue a token for this VM only
const { token } = await vm.issueToken({
	subject: "user-123",
	expiresIn: 3600,
});

// Client: call the VM directly
const userClient = createAgentOsClient({
	endpoint: "https://api.rivet.dev",
	namespace: "my-namespace",
	token,
});
const userVm = userClient.getForId("agentOS", vmId);
```

```bash cURL
curl -X POST "https://api.rivet.dev/auth/tokens" \
  -H "Authorization: Bearer $RIVET_TOKEN" \
  --json @- <<EOF
{
  "namespace": "$RIVET_NAMESPACE",
  "subject": "user-123",
  "duration": 3600,
  "grants": [{
    "resource": "actor_gateway",
    "target": { "id": "$VM_ID" },
    "operations": ["read"]
  }]
}
EOF
# → { "token": "…", "expires_ts": … }
```

</CodeGroup>

The cURL examples below call the VM with that scoped token as `$VM_TOKEN`.

## Files and processes

<CodeGroup>

```ts TypeScript @nocheck
await vm.v1.filesystem.writeFile({
	path: "/home/agentos/hello.txt",
	content: "Hello, world!",
});

const result = await vm.v1.process.run({
	command: "cat",
	args: ["/home/agentos/hello.txt"],
	options: { captureStdio: true },
});
console.log(result.stdout, result.status.exitCode);
```

```bash cURL
curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.filesystem.writeFile" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{
    "path": "/home/agentos/hello.txt",
    "content": "Hello, world!"
  }]}'

curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.process.run" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{
    "command": "cat",
    "args": ["/home/agentos/hello.txt"],
    "options": { "captureStdio": true }
  }]}'
```

</CodeGroup>

`v1.process.run` takes an executable and an argument array. Run `sh` with `-c`
when you need shell parsing.

## Output survives reconnects

Process and terminal output is retained on the VM. After a disconnect, page
through it with a cursor instead of losing it.

<CodeGroup>

```ts TypeScript @nocheck
const server = await vm.v1.process.spawn({
	command: "node",
	args: ["/home/agentos/server.js"],
});

// Later, from any client
const { events, nextCursor } = await vm.v1.process.output.read({
	process: server,
});
```

```bash cURL
curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.process.spawn" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{
    "command": "node",
    "args": ["/home/agentos/server.js"]
  }]}'
# → { "output": { "generation": 1, "pid": 42 } }

# Later, from any client
curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.process.output.read" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{"process": {"generation": 1, "pid": 42}}]}'
```

</CodeGroup>

## Live events

Connect to the VM to receive events as they happen. Events are hints; use the
pull actions to recover anything missed while disconnected.

```ts TypeScript @nocheck
const conn = vm.connect();
await conn.ready;

conn.on("vm.booted", () => console.log("VM is ready"));
conn.on("vm.shutdown", (payload) => console.log("shutdown:", payload.reason));

const spawned = await conn.v1.process.spawn({
	command: "node",
	args: ["/home/agentos/server.js"],
});

conn.on("process.output", (data) => {
	if (data.process.pid !== spawned.pid) return;
	console.log(data.stream, new TextDecoder().decode(data.data));
});
conn.on("process.exit", (data) => {
	if (data.process.pid !== spawned.pid) return;
	console.log("exited with code", data.status.exitCode);
});
```

The VM starts lazily on the first agentOS action after the actor wakes.

## Language runtimes

Run JavaScript, TypeScript, and Python directly, with npm and pip installs
built in.

<CodeGroup>

```ts TypeScript @nocheck
await vm.v1.javascript.execute({ source: "console.log(1 + 2)" });

const { value } = await vm.v1.python.evaluate({ expression: "21 * 2" });
```

```bash cURL
curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.javascript.execute" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{"source": "console.log(1 + 2)"}]}'

curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.python.evaluate" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{"expression": "21 * 2"}]}'
```

</CodeGroup>

## Durable configuration

Configuration is stored with the VM and versioned. Patch it with
compare-and-set; `v1.vm.status` reports when a change needs a restart.

<CodeGroup>

```ts TypeScript @nocheck
const { revision } = await vm.v1.config.get({});

await vm.v1.config.patch({
	expectedRevision: revision,
	patch: { environment: { DEBUG: "1" } },
});
```

```bash cURL
curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.config.get" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{}]}'
# → { "output": { "revision": 3, … } }

curl "https://api.rivet.dev/gateway/$VM_ID/action/v1.config.patch" \
  -H "x-rivet-token: $VM_TOKEN" \
  --json '{"args": [{
    "expectedRevision": 3,
    "patch": { "environment": { "DEBUG": "1" } }
  }]}'
```

</CodeGroup>
