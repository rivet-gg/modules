Servers inside the VM listen on VM-local ports. They are not exposed on the
host network. `network.httpRequest` proxies one bounded HTTP request from the
host to a VM loopback port and returns the buffered response.

`vm.fetch(port, request)` sends a standard `Request` and returns a `Response`.
`fetchStreamStart`, `fetchStreamRead`, and `fetchStreamCancel` deliver a
response body in bounded chunks, so the caller owns backpressure for large
responses.

## Guest network access

Guest listeners and loopback traffic stay inside the VM. Outbound access is
limited to the sidecar's default allowlist unless the `network`
[permission](/agentos/docs/permissions) scope allows more. Requests from the
host through `httpRequest` enter the VM from the host side, so they are subject
to loopback confinement but not to the guest egress policy.

Embedded Core does not create public URLs for VM ports. To expose a VM server
to browsers, route requests through your application and forward them with
`httpRequest` or `fetch`, or use a hosted VM's
[expiring previews](#hosted-api).

## Hosted API

Hosted VMs proxy requests with `v1.network.fetch` and the pull-based
`v1.network.fetchStream.start`, `read`, and `cancel` actions.

Hosted VMs can also expose any port through an expiring preview. A preview is a
signed URL path that proxies HTTP to a port inside the VM until it expires or is
revoked.

```ts TypeScript @nocheck
await vm.v1.process.spawn({
	command: "node",
	args: ["/home/agentos/app.js"],
});

const preview = await vm.v1.network.preview.create({
	port: 3000,
	ttlMs: 60 * 60 * 1_000,
});
console.log(preview.path, new Date(Number(preview.expiresAtMs)));

await vm.v1.network.preview.expire({ token: preview.token });
```

`config.preview.defaultTtlMs` sets the default lifetime. Previews enter the VM
from the host side, so they are subject to loopback confinement but not to the
guest egress policy.
