---
title: "External Sandboxes"
description: "Mount a full external sandbox into an agentOS VM for workloads that need a real Linux kernel."
---

When a workload needs a full Linux environment, attach an external sandbox to
a library VM with the `sandbox` option. External sandboxes rely on trusted host
callbacks and mounts, so they are not available on hosted VMs. agentOS mounts the sandbox filesystem into
the VM at `/mnt/sandbox` and registers `agentos-sandbox` host functions for
running commands and listing processes in the sandbox.

<CodeSnippet file="examples/quickstart/sandbox/index.ts" />

Guest code reads and writes sandbox files the same way it reads local files.
Providers live in `@rivet-dev/agentos-sandbox`.

The sandbox bridge runs through trusted host callbacks in the embedding
process, so credentials for the sandbox provider stay on the host.

See [agentOS vs Sandbox](/agentos/docs/versus-sandbox) to decide when a
workload needs one.
