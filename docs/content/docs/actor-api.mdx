description: "Configure and operate a hosted agentOS VM through a typed RivetKit actor handle or the HTTP gateway."
---

The hosted `agentOS` actor is a fixed Rust actor. Use a normal RivetKit client
with the generated `AgentOsRegistry` contract. The `createAgentOsClient`
helper only supplies that type parameter and does not add another transport or
API layer. See [Hosted VMs](/agentos/docs/hosted) to get started.

Creation input is considered only when RivetKit creates the actor. Calling
`getOrCreate` with different creation input for an existing key does not
reconfigure it. Use the config actions for later changes.

## Configuration

`v1.config.get` returns the durable desired config and its revision.
`v1.config.set` replaces the complete config. An omitted field selects its
default. `v1.config.patch` applies an RFC 7386 JSON Merge Patch to the current
desired config.

Merge Patch recursively merges objects and replaces arrays as complete values.
Setting a property to `null` removes the override, which selects its default.
Both mutation actions accept `expectedRevision` for compare-and-set updates.
A stale revision fails without changing durable state.

```ts TypeScript @nocheck
import type { AgentOsActorCreateInput } from "@rivet-dev/agentos";

const createInput: AgentOsActorCreateInput = {
	config: {
		environment: { CI: "true" },
		preview: { defaultTtlMs: 30_000 },
		filesystem: {
			root: { type: "durable" },
			mounts: [{ path: "/data", backend: { type: "durable" } }],
		},
		software: [{ url: "https://packages.example/tool.aospkg" }],
	},
};

const vm = client.agentOS.getOrCreate(["my-vm"], {
	createWithInput: createInput,
});

await vm.v1.config.set({
	config: { limits: { tls: { maxBufferedBytes: 2048 } } },
});
```

Core owns VM defaults and validation; the generated client does not copy those
defaults. Hosted-only policy, including preview leases and the filesystem
registry, is normalized by the actor.

When a VM is running, the actor asks that VM's sidecar to compare the resolved
creation policies for supported runtime fields. Setting an explicit value equal
to the active default does not by itself require a restart. Software sources,
hosted filesystem policy, and any future fields not explicitly covered by that
comparison remain replacement-triggering.

## VM lifecycle

`v1.vm.status` reports the active generation, applied config revision, package
readiness, lifecycle state, and recent issues. A desired config can be durable
while the active generation reports that a restart is required.

`v1.vm.restart` stops the active VM, waits for bounded shutdown, and starts a
new generation from the latest desired config. Process, terminal, context, and
network stream handles include their generation. Using an old handle after a
restart fails as `stale_generation`.

Lifecycle notifications use the `vm.booted`, `vm.shutdown`, and
`vm.limitWarning` events. `vm.shutdown` carries a `reason` of `"sleep"`,
`"destroy"`, or `"error"`.

## Pull APIs and events

Live events reduce latency, but bounded pull actions are the recovery path
after a disconnect or inspector reload. Event names are not versioned.

| Resource | Pull action | Events |
| --- | --- | --- |
| Process | `v1.process.output.read`, `v1.process.wait` | `process.output`, `process.exit` |
| Terminal | `v1.terminal.output.read`, `v1.terminal.wait` | `terminal.output`, `terminal.exit` |
| HTTP response | `v1.network.fetchStream.read` | None |
| VM | `v1.vm.status` | `vm.booted`, `vm.shutdown`, `vm.limitWarning` |
| Cron | `v1.cron.list` | `cron.fired` |

Process and terminal replay use a generation-scoped sequence cursor. Request
limits bound both the number of events and their aggregate bytes. Network
response streams are pull-based so each action is bounded and the caller owns
backpressure.

## Errors

| Code | Cause |
| --- | --- |
| `stale_generation` | A process, terminal, context, or stream handle from before a `v1.vm.restart` was used. |
| `expired` | A fetch-stream handle expired. |
| `timeout` | A required package-resolution deadline passed. |
| `not_found` | A closed terminal's replay was evicted from the bounded retention window. |

Final terminal output and its confirmed exit remain readable after exit within
the bounded closed-terminal retention window. Events are hints; use replay to
recover missed output.

## Actions

Every public action is versioned under `v1`. In TypeScript, call
`vm.v1.<group>.<action>(input)`. Over HTTP, call
`POST /gateway/{actor_id}/action/v1.<group>.<action>` with
`{ "args": [input] }`.

| Group | Actions |
| --- | --- |
| `config` | `get`, `set`, `patch` |
| `vm` | `status`, `restart` |
| `filesystem` | `readFile`, `writeFile`, `readFiles`, `writeFiles`, `stat`, `exists`, `mkdir`, `readdir`, `readdirEntries`, `readdirRecursive`, `move`, `remove`, `listMounts`, `export` |
| `process` | `run`, `spawn`, `get`, `list`, `tree`, `wait`, `signal`, `stdin.write`, `stdin.close`, `pty.resize`, `output.read` |
| `terminal` | `open`, `list`, `stdin.write`, `pty.resize`, `output.read`, `wait`, `close` |
| `network` | `fetch`, `fetchStream.start`, `fetchStream.read`, `fetchStream.cancel`, `preview.create`, `preview.expire` |
| `software` | `install`, `uninstall`, `list` |
| `cron` | `schedule`, `list`, `cancel` |
| `contexts` | `create`, `get`, `list`, `reset`, `delete` |
| `javascript` | `execute`, `evaluate`, `executeFile`, `spawn`, `spawnFile`, `npm.install`, `npm.runScript`, `npm.runPackage` |
| `typescript` | `execute`, `evaluate`, `executeFile`, `spawn`, `spawnFile`, `check`, `checkProject` |
| `python` | `execute`, `evaluate`, `executeFile`, `executeModule`, `spawn`, `spawnFile`, `spawnModule`, `install` |

The hosted contract has no agent sessions and no shell-string `process.exec`.
Private cron and maintenance actions are not part of the client.

## Contract compatibility

The package exports `AGENTOS_API_VERSION`, `AGENTOS_CONTRACT_MAJOR`,
`AGENTOS_CONTRACT_HASH`, and `AGENTOS_CAPABILITIES`. Rust DTOs and the action
registry generate the TypeScript surface. The actor and client package ship in
lockstep during the alpha contract period.

The contract is currently `agentos-sdk.dev/v1alpha1`, major `1`. The hash covers
the canonical public actions, events, DTOs, and capabilities. Private cron and
maintenance actions are excluded from both the generated client and hash.

## Inspector

The Inspector is a client of the same public contract. Its filesystem,
process, terminal, software, preview, config, status, and limit views do not
receive private actor access. The UI can read desired configuration and VM
status, restart the VM, and show runtime issues, but it cannot edit host
mounts.

Published Linux services binaries and the services container include the built
tabs beside the executable, so they are registered automatically. A source or
custom deployment can point the service at another built copy:

```sh
AGENTOS_INSPECTOR_TABS_DIR=node_modules/@rivet-dev/agentos/assets/inspector-tabs-app \
  rivet-services start
```

Startup fails if an explicit `AGENTOS_INSPECTOR_TABS_DIR` does not contain
`index.html`.

## Embedded API

Embedded Core exposes the same VM capabilities without RivetKit actor
lifecycle, durable actor config, previews, or hosted URL-only policy. Read more
in the [embedded API quickstart](/agentos/docs/quickstart-embedded).
